- **驱动轮 `cmd_vel:=cmd_vel_raw` 在 URDF 里写死**：底盘只听 `/cmd_vel_raw`，
  这是"建图模式为什么要直发原始话题"的根因。

## 4 为什么槽内必须两段式进槽

这是几何决定的，不是策略偏好：

| 量 | 数值 |
|---|---|
| 槽内净宽 | 0.80 m（实测地图 0.72 m） |
| 车体边长 | 0.50 m |
| 车体半对角 | 0.354 m |
| **四周剩余** | **0.19 m**（实测 0.11 m） |

车在槽内**原地转身物理上做不到**（余量约 7 mm，会被膨胀层与栅格化吃掉）。
而 Nav2 的 `SimpleGoalChecker` 要求航向 ≤0.20 rad，转不动 → 判无进展 → spin/backup 恢复行为
→ 槽内被挡 → 越转越偏 → 超时（实测进槽到位后航向差 **138°**）。

所以：

1. **纠偏挪到槽外**：先到「X号货架」对位（车头正对槽口），槽内最后 1.37 m 是直线
2. **槽内到点以位置为主**：0.12 m / 0.35 rad / 稳定 0.6 s，判到就 `cancelTask()` 再搬货
3. **出槽只能倒车**：控制器必须允许倒车（`min_vel_x = -0.20`）

### 4.1 倒车与锥角（两条"别开大"的教训）

**后方保护锥 `rear_half_angle_deg` 不能开大**：槽内两侧壁与车身平行，车心离壁仅 0.361 m，
锥一放宽就把侧壁读成"身后有障碍"，倒车被自己的减速逻辑压住 → **"能进不能出"复发**。

实测（5 槽 × 整条倒车路径 × 横向 ±0.10 m × 航向 ±3°）后方锥最小距离：

| 锥角 | 最小距离 | 结果 |
|---|---|---|
| ±20° | 1.20 m | 干净 |
| ±25° | 0.54 m | 擦到侧壁、触发减速 |
| ±45° | 0.34 m | 近刹停 |

故取 **20°**。

**接管闸门 `takeover_half_angle_deg` 也不能开大**：前锥 45° 的边界会扫到平行于车身的槽侧壁——
车心最多偏 0.361 − 0.250 = 0.111 m，近侧壁距车心 0.250 m，45° 射线命中 0.250/sin45° = 0.354 m
≤ take(0.45) → "前方很近"的假象骗开闸门；左右壁距一差就超过 0.10 偏置阈值 → 夺向。
可两侧壁平行，往哪偏都蹭墙。

解析临界 `h > asin(0.250/0.55) = 27.0°`，实测临界 30°~35°，取 **20°**。
实测进槽 36%~47% 采样被夺向 → 收到 20° 后为 **0**。

**到点对准不能被避障夺向**：槽内前方恒为槽底挡板（≈0.38 m，恒小于接管阈值 0.45 m），
所以到点后 Nav2 只发角速度做航向对准时，避障若仍接管角速度，就会把对准换成固定 0.5 rad/s 的左右摇摆
→ 航向永远进不了 `yaw_goal_tolerance`(0.20 rad) → `goToPose` 不返回 → 任务死等 180 s 报错。
故 `reactive_avoid` 只在**真正往前挪**（`v_nav > 0`）时择向；`v_nav ≈ 0`（对准/停车）与
`v_nav < 0`（倒车）都不接管角速度。**调容差无效**——`SimpleGoalChecker` 的 `stateful: True`
一旦位置达标就只判航向。

## 6 目标点判据

`agv_common/goal_check.py → MapChecker.check_point`：

| 判据 | 说明 |
|---|---|
| ① 在地图内 | 目标格必须落在 PGM 范围内 |
| ② 非障碍 / 非未知 | 灰度 < `occupied_gray`（默认 65）视为占用 |
| ③ 净空足够 | 到最近障碍距离 ≥ `robot_clearance`（默认 0.30 m） |

- 净空用四邻域 BFS 距离场算，格数 × 分辨率换算成米；`clearance_at()` 可单独查某点净空
- `bottleneck(sx, sy, gx, gy)` 给"起点→目标"路径最窄处的净空，判断物理上开不开得过去
- 这是全项目**唯一**的"能不能去"判据：`goto` 坐标与导航前的点位都问它
- `map_yaml` 非空则读图；**读不到图不抛异常**，记原因后退化为 `field_*` 矩形，并在启动日志说明用哪种
- 与 `map_server` 解码一致：灰度 205 这类未观测格按可通行处理（trinary），不额外拦截导航器能走的点

## 7 改场景怎么做

场景由 `tools/make_world_map.py` 一份参数化布局驱动，**世界与地图必须同源**：

1. 改脚本顶部参数区：`WALLS`（墙）、`SLOT_SPOTS`（槽位落点）、`SLOT_*`（槽型尺寸）、`CARGO_SPOTS`（货物落座）
2. `python3 tools/make_world_map.py` → 重出 `world666.world` 与**参考**栅格 `world666map_ref.pgm/.yaml`，
   并刷新 `waypoints.yaml` / `routes.yaml`，打印场地范围与自检结果
3. 脚本内部用 `agv_common.map_check.MapChecker` 自检：逐点判净空（≥0.30 m）+ 打印"起点→各点"瓶颈宽
4. **实测地图不会被脚本覆盖**（只写 `_ref`）。换世界后要重新建图，由控制台建图模式保存为
   `maps/world666map/world666map.pgm/.yaml`，再 `colcon build` 装进 share
5. 世界或地图变更后，同步 `task.yaml` 的四个 `field_*` 兜底边界（对照 §2.2）

★ 槽位落点与槽内点位是**成对**的：改了 `SLOT_SPOTS` 就要重算槽内点（槽口中心内推 0.468 m），
否则车会停在货物旁边顶空。
