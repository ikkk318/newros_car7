## 一、git 到底是什么（一句话）

**git 是给代码拍"快照"的工具。** 每改完一批东西，你按一下快门，它就把当前所有
文件的完整状态存成一张照片。以后任何时刻，你都能：
- 翻看以前每一张照片（改了什么、什么时候改的）；
- 把文件"退回"到某一照片的状态（改坏了不怕）；
- 给每张照片写一句说明（"我给任务层加了搬运闭环"）。

## 二、几个词，用人话解释

| 词 | 人话 |
|---|---|
| **仓库 (repository)** | 装所有快照的那个"相册"。`git init` 就是在当前目录建这个相册。 |
| **提交 (commit)** | 按一次快门，存一张照片。每张照片有编号、时间、你写的说明。 |
| **暂存 (add)** | 挑哪些改动要进这张照片（先放上"待拍台"）。 |
| **工作区** | 你现在真实在编辑的那些文件（照片之外的"现场"）。 |
| **.gitignore** | 一张"黑名单+白名单"，写明**哪些文件永远别进相册**。 |
| **分支 (branch)** | 相册的"平行时间线"。默认那条叫 `main`，你暂时不用管它。 |

## 三、你项目里的 `.gitignore` 在挡什么

你项目根目录的 `.gitignore` 是关键。这里是**排除式**写法（默认全收，点名挡几条），
比白名单好维护——以后新增目录不用再去改放行链。逐段讲：

```
build/ install/ log/     ← ROS 编译产物。每次 colcon build 都会重新生成，
                            是"垃圾照片"，进库只会把相册撑爆，所以挡掉。
__pycache__/ .pytest_cache/
*.pyc *.egg-info/        ← Python 运行时的缓存文件，同理挡掉。
.vscode/browse.vc.db*    ← 编辑器自己的代码索引数据库，你这有 1.1G！必须挡。
                            （同目录的 settings.json 是手工配置，只有 4K，留着）
.bak/ *.bak              ← 改代码前的手工备份（app.js.181221 这类），有了 git 就不需要了。
maps/.launch/            ← 给中文地图名做 ASCII 软链的临时目录，每次起导航重建，
                            里面是绝对路径软链，换机器就是废的。
tools/webtest/*.log      ← 测试脚本每跑一次刷一批日志，别入库。
tools/webtest/*.png
```

**结果**：首次提交纳入 **205 个文件**（真正手写的源码 + 文档 + 地图），
`build/install/log`、420K 手工备份、1.1G 编辑器索引全部被挡在外面。

> 记忆点：**"入库的应该是'你手写的'，不是'机器生成的'。"**
> 机器生成的（编译产物、缓存、数据库）任何时候都能重新生成，不该进相册。
>
> 例外：`maps/` 下的地图（pgm + yaml + 点位 + 路线）**要入库**。它不是机器
> 造的垃圾，是你现场标定出来的成果，重新建一次要跑一圈车。

## 四、日常只要记这 4 条命令

```bash
# 1. 看看现在改了哪些文件（最常用，先看再决定）
git status

# 2. 把改动挑进来准备拍照（. 表示"当前目录所有改动"）
git add .

# 3. 拍一张照片，写说明（说明一定要写，不然以后看不懂）
git commit -m "说明我这次改了啥"

# 4. 回顾一下拍过的照片
git log --oneline
```

**每次改完一段、确认能跑，就 `add` + `commit` 一次。** 说明写人话即可，
比如 `"修复纯数字点名叫不动车"`、`"加了点位预检"`。

## 五、出事时的"后悔药"

```bash
# 某个文件改坏了，想退回上次提交的样子
git checkout -- 文件名

# 看看某次提交到底改了什么
git show 提交编号
```

> ⚠️ 注意：`git checkout -- 文件` 会**丢掉你没提交的改动**。
> 所以养成习惯：改到阶段性成果就先 commit，别攒一大堆没提交的改动。
